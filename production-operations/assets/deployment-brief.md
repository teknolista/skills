# Deployment brief

Use the project's existing change record when it covers these fields. Fill applicable items and mark unknowns with an owner and the action they block. Record secret references only.

| Item | Project input |
| --- | --- |
| Intended outcome and mode | Plan, configure, deploy, operate, recover, or retire. |
| Source | Repository, authoritative contract, commit/ref, CI project, artifact and registry. |
| Execution environment | Agent/runner location, provider, account, tenant/subscription/project, region, target and environment. |
| Workload | Runtime and process types, protocols, dependencies, data, traffic/capacity, budget, availability and recovery objectives. |
| Scope | Resources and environments allowed, public exposure, budget, allowed writes, maintenance window and change authority. |
| Access | Bootstrap owner, login/profile or connector, pipeline trust/role, runtime/migration/observer identities, approved secret stores and private network path. |
| Baseline | Existing controller/IaC and state, deployed revisions, DNS/TLS ownership, data version and current health. |
| Change | Resource plan and ordering, artifact promotion, migrations and data compatibility, traffic/trigger strategy and estimated cost. |
| Verification | Acceptance checks, synthetic identity/data, baseline, thresholds, observation window, evidence and cleanup. |
| Recovery | Prior revisions, data recovery and reconciliation, abort triggers, action owner and escalation. |

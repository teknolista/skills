# Cloudflare

## Match the workload

Use Workers for compatible HTTP/edge, queue or scheduled handlers. Validate runtime APIs and Node.js compatibility, CPU and execution limits, protocol behavior, placement and origin latency with the deployed runtime. Evaluate Cloudflare Containers for suitable custom runtimes and verify their lifecycle, scaling, rollout and persistence constraints. For a conventional service on another host, Cloudflare DNS, proxy, WAF or Tunnel can own ingress while the host platform runs the application. Confirm origin access restrictions, routing and TLS end to end.

Choose D1, Durable Objects, KV, R2, Queues or an external database with suitable connectivity according to transactional, consistency, retention and retry requirements. Treat staging and production binding IDs as data boundaries. Use distinct queues, data and secrets when test effects must stay isolated.

## Establish access

Get account ID, zone IDs, Worker names/environments, routes/domains and binding IDs. For automation, use a protected, narrowly scoped API token with only the supported product/resource rights. Workers deploy and zone route updates may need distinct grants. Pass `CLOUDFLARE_ACCOUNT_ID` and inject `CLOUDFLARE_API_TOKEN` through the protected CI secret mechanism for Wrangler. Human OAuth can suit interactive discovery when its scope is acceptable. Check `wrangler whoami` and an exact in-scope resource read, then inspect the environment's binding and secret references. Keep separate identities/tokens for DNS, deploy and Tunnel administration where effects differ. A Tunnel connector token authorizes a connector, while control-plane provisioning needs its own authority.

## Release and MCP

Pin Wrangler and inspect the generated bundle and environment configuration. For Workers where applicable, upload a version and promote through Workers versions/deployments, checking the observed version, route and live behavior. Verify effective bindings for both revisions, including the recovery candidate. If the old version points at production data from staging, establish a compatible baseline with safe staging bindings before splitting traffic. Check queue and scheduled trigger behavior separately. Pending Durable Object class lifecycle changes require a direct deploy under the documented migration procedure. Worker rollback cannot cross such a change, whether managed through exports or legacy migrations. Plan a forward recovery path and verify connected resources and data separately. For Containers, use its own rollout guidance and verify active instances as well as the Worker version. For an external origin, verify the host release independently of Tunnel and DNS changes.

Use the **Cloudflare API MCP Server** at `https://mcp.cloudflare.com/mcp` for authorized account queries or scoped API actions. Use `https://docs.mcp.cloudflare.com/mcp` for documentation lookup. The main managed remote server supports OAuth and scoped bearer-token access according to the provider guide. Its search/execute surface is broad. Inspect the intended endpoint, request and side effects before execution, and use only necessary provider permissions. Use Wrangler for reproducible Worker builds and deploys, and Cloudflare API/IaC for reviewed account changes.

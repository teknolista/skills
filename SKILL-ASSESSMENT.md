# Software factory skill assessment

This is a historical record of the earlier 17-package assessment. See the [collection review](COLLECTION-REVIEW.md) and [evaluation guide](SKILL-EVALUATION.md) for later changes and trials.

Reviewed the supplied compilation of model responses on 2026-11-09. The attachment supplied ideas and claims for verification. The repository review used the checked-out collection at baseline `fd8633a` and the user's commercial software scope.

## What changes the outcome

The responses converge on four failure classes: ambiguous intent, missing local knowledge, weak verification, and drift across changes. They differ on how much process to impose. Adopt focused discovery when a decision changes the result, retain project vocabulary in its canonical home, and prefer a check that observes the actual behavior. An independent review evaluates both accepted behavior and applicable standards. An agent can complete routine work under established authority while reporting missing evidence or consequential decisions.

The benchmark numbers in the attachment describe an older revision. The authors' October 2026 preprint revision reports 98 skills, 92 without a statistically significant effect, and a mean pass ratio of 76.6% without skills versus 76.9% with skills. Its tasks and models differ from this collection and Castas. Neither the paper nor the endorsements estimate this project's gains. The strongest reason to adopt a skill is a repeatable improvement on a relevant task at acceptable cost. [SWE-Skills-Bench v2](https://arxiv.org/abs/2603.15401v2)

Use compact project instructions for recurring local facts, on-demand skills for distinct workflows, and executable checks for objective gates. The [evaluation procedure](SKILL-EVALUATION.md) separates explicit invocation from automatic routing and records quality, safety, and effort in matched runs. Stars, installation counts, and broad productivity claims from the attachment were excluded as effectiveness evidence. [Agent Skills specification](https://agentskills.io/specification), [Thoughtworks Technology Radar](https://www.thoughtworks.com/radar/techniques/agent-skills)

## Validation record

- The independent diagnostic and test-authoring smoke trial used a disposable Python queue with a cross-tenant receipt collision. The original suite passed 1 test. The focused regression failed before the fix with equal receipts, then passed after the receipt key included the tenant. The original reproduction changed from two recorded jobs to three while the within-tenant retry kept its receipt. The final suite passed 2 tests. This was one forward run with both skills and no baseline model run. No actual API server, MCP server, Android app, deployment, or cost comparison was exercised by that trial.
- All 17 skill packages passed `skill-creator/scripts/quick_validate.py`. The local check inspected 85 Markdown files and 564 links or anchors, and reconciled README and PentaPRO template versions. Each new entrypoint contains 379–446 words, including its metadata. Word count describes package size only. Token cost and automatic activation were not measured.
- Existing executable checks passed: `python3 -m unittest discover -s ui-design/scripts/tests -v` (24), `python3 -m unittest discover -s pr-quiz/scripts/tests -v` (12), and `node pr-quiz/scripts/tests/workflow.cjs` (25 offline scenarios). The native Android packages and Android UI references were preserved. No Castas build or live GitHub workflow was run for this change.
